# Current scope and Android handoff

## Implemented now

- Real React/TypeScript/Vite web application; no Streamlit runtime.
- Anonymous showcase session with automatic expired-token recovery.
- Fixed ₹10K–₹1L monthly contribution and 24/36/48/60-move campaigns.
- Governed 50-security universe derived from Vriddhi artifacts.
- Deterministic generated market with financial metrics and Nifty benchmark.
- Hidden whole-share feasible reference portfolio.
- Whole-share BUY/SELL execution, cash accounting and 90% deployment rule.
- Deterministic score, move classification, explanation, outcome and rating.
- Immersive market terminal with spreadsheet-style analysis, generated newsroom, comprehensive
  movers, stock research workstation and order workbench.
- Campaign state, latest result, resignation, lesson and puzzle APIs.
- Docker build, Render auto-deployment and health endpoint.
- Simulation and private-oracle contract tests.

## Present but still being product-tested

- review/commit and score-reveal choreography;
- campaign progress and historical move analysis;
- puzzle and lesson breadth;
- player profile, rankings and achievement depth;
- final campaign report and replay value;
- responsive behaviour below desktop width;
- empty, error, offline and long-campaign usability states.

## Deliberately deferred

- Google login and durable player accounts;
- public leaderboard and multiplayer/social features;
- live news, quotations or brokerage integration;
- real-money execution;
- durable database, multi-instance scaling and production analytics;
- native Android application and Play Store release;
- push notifications, subscriptions or monetisation.

## Web-complete gate

Android replication should begin only when the web version has:

1. a stable start-to-completion campaign loop;
2. accepted market, stock, order, review, result and progress UX;
3. stable public API payloads and error codes;
4. tested refresh/idempotency and long-campaign recovery;
5. final simulation/legal language;
6. final product terminology and visual tokens;
7. an agreed mobile information-priority map.

## Android replication contract

Android is a new client, not a new engine. It must consume the same `/api/v1` contracts and preserve:

- campaign amount/horizon immutability;
- one complete portfolio move per month;
- integer paise and whole-share accounting;
- hidden reference and temporal integrity;
- scoring/classification rules;
- persistent simulation disclosure;
- decision-quality/outcome separation.

The mobile client may redesign layout, gesture and navigation for a small screen. It must not fork
financial logic, reproduce the hidden engine on-device, or reduce simulation disclosure.

## Recommended handoff artifacts

Before Android starts, freeze:

- an OpenAPI or equivalent machine-readable contract;
- web golden-path screenshots and interaction recordings;
- design tokens and component states;
- campaign/move state diagrams;
- API fixtures for every major state and error;
- cross-client contract tests;
- Android threat model and offline/resume strategy.
